What happens when input is bigger than the box you put it in?

A C function stores its local variables on the stack. Right above those locals sit the values the CPU needs to get back home: the saved frame pointer and the return address. A copy function that never checks length will happily keep writing past the end of the buffer and straight through them. Type something below and watch it happen, one byte at a time.

How to prevent it

        
    
          
  • Use length-aware APIs: strncpy, snprintf, strlcpy, or C++ std::string.
    • 
          
  • Always reserve room for the '\0': sizeof buf - 1, then terminate manually.
    • 
          
  • Keep compiler defenses on: stack canaries, ASLR, non-executable stack (NX/DEP).
    • 
          
  • Treat <= in a bounds check as a code smell — it is the classic off-by-one.
    • 
        

      

    

  










  

    
Numbers in C live in fixed-width boxes too.

    

      An int is not a mathematical integer — it is a fixed number of bits. When a result needs more bits
      than the type has, the extra bits are simply thrown away. The value wraps around, and code that assumed
      "bigger input → bigger number" quietly breaks.

Why this matters

          
    
            
  • Signed overflow in C/C++ is undefined behaviour — the compiler may assume it never happens and delete your
              if (x + 1 < x) check entirely.
    • 
            
  • Unsigned overflow is defined to wrap modulo 2N — legal, but still a logic bug if you did not expect it.
    • 
            
  • Session counters, timestamps, and reference counts that wrap can resurrect freed objects or reset limits.
    • 
          

        

      

    

  


  
  

    

      

        

          
The classic allocation bug

          
/* count comes from the network / a file header */
uint32_t count = 16;
Item *items = malloc(count * sizeof(Item));   /* sizeof(Item) == 16 */
for (uint32_t i = 0; i < count; i++)
    items[i] = read_item();                   /* writes count * 16 bytes */

  • Fix: check before you multiply — if (count > SIZE_MAX / sizeof(Item)) abort();

One bounds check, two different types

          
#define MAX 256
char dst[MAX];

void handle(char *src, int len) {       /* signed */
    if (len > MAX)
        return;                     /* "too big" rejected */
    memcpy(dst, src, len);          /* len converts to size_t (unsigned) */
}

    • Comparing a signed value against an unsigned one converts the signed value — negative becomes enormous.
      • 
            
    • Use size_t for sizes, and reject negatives explicitly: if (len < 0 || len > MAX) return;
      • 
            
    • Turn on -Wsign-compare -Wconversion and treat the warnings as errors.
